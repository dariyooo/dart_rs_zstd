# dart_zstd

Zstandard for Dart. Direct FFI bindings to the reference [libzstd][zstd], built
from source and bundled as a **native asset** — no plugin, no platform channels,
no Flutter dependency, nothing to install.

The C library sources are vendored under `third_party/libzstd` and compiled by
`hook/build.dart`; `lib/src/bindings.g.dart` is generated by `ffigen` from
upstream's `zstd.h` and `zdict.h`. A pinned `third_party/zstd` git submodule
tracks upstream, and a weekly workflow refreshes the vendored copy when a new
libzstd is released.

## Install

```console
dart pub add dart_zstd
```

Requires Dart 3.10+ and a C compiler (Xcode CLT, gcc/clang, or MSVC): the hook
builds libzstd from the bundled sources on first build. The sources ship with
the package, so nothing else is needed — pure Dart programs pass
`--enable-experiment=native-assets`; Flutter apps need nothing.

## Whole buffers

```dart
import 'package:dart_zstd/dart_zstd.dart';

final packed = zstd.encode(bytes);
final same = zstd.decode(packed);

// Denser, with a frame checksum and four worker threads.
const dense = ZstdCodec(level: 19, checksum: true, workers: 4);
```

Reuse a context when compressing many payloads — it keeps zstd's tables
allocated between calls:

```dart
final compressor = ZstdCompressor(level: 6);
try {
  for (final record in records) sink.add(compressor.compress(record));
} finally {
  compressor.close();
}
```

## Streams

`ZstdCodec` is a `dart:convert` `Codec`, so its converters are also
`StreamTransformer`s. Nothing larger than one zstd block is held in memory.

```dart
await File('in.txt')
    .openRead()
    .transform(zstd.encoder)
    .pipe(File('out.zst').openWrite());
```

Decoding accepts any number of concatenated frames, and fails if the input stops
mid-frame.

## Dictionaries

A dictionary is what makes zstd win on many small, similar payloads — a single
JSON record can go from 63 bytes to 22. Train one from your own data:

```dart
final dictionary = ZstdDictionary.train(samples, maxSize: 16 * 1024);
await File('records.dict').writeAsBytes(dictionary.bytes);
```

Digest it once, then share it across compressions:

```dart
final forCompression = dictionary.prepareForCompression(level: 10);
final forDecompression = dictionary.prepareForDecompression();

final codec = ZstdCodec(
  compressionDictionary: forCompression,
  decompressionDictionary: forDecompression,
);
```

Dictionaries are byte-compatible with `zstd --train`, so one side can be the
command line tool. Beyond the default trainer, `ZstdDictionary.trainWithCover`
and `.trainWithFastCover` expose the COVER and fastCover algorithms with their
full parameter sets (and their self-optimising modes), and
`ZstdDictionary.fromContent` finalises a dictionary from content you picked
yourself.

For one-off shared context that is cheaper than a dictionary, both the
compressor and the decompressor take a prefix via `usePrefix`.

## Everything else

| | |
|---|---|
| `Zstd` | library version, level range, `compressBound` |
| `ZstdFrame` | header inspection: content size, compressed size, dictionary id |
| `ZstdCompressionParameter` | window/hash/chain logs, strategy, LDM, workers, job size, … each with its `bounds` |
| `ZstdStreamCompressor` / `ZstdStreamDecompressor` | the incremental engines, if you do not want `dart:convert` |
| `ZstdCompressor.setPledgedSourceSize` | records the exact size in the frame header |

Native resources (`ZstdCompressor`, dictionaries, stream engines) release on
`close()`, and are also attached to a `NativeFinalizer`, so a dropped handle is
freed rather than leaked.

The few remaining libzstd entry points that have no idiomatic Dart shape — the
block-level API, `ZSTD_CCtx_params` objects, the external sequence producer —
are still generated and callable from `lib/src/bindings.g.dart`.

## Updating libzstd

The `third_party/zstd` submodule is pinned to a release tag. A weekly workflow
checks upstream for a new stable release, bumps the submodule, refreshes the
committed `third_party/libzstd` copy, regenerates the bindings, bumps the version
and opens a pull request; every run appends a line to
`.github/upstream-check.log`.
